# ADR 0001：Chunk は PDF の物理ページをまたがない

状態：採用。`backend/rag.py::chunks_from_pages` に適用。

## 背景

回答からアップロードした原 PDF に戻り、根拠を確認する必要があります。紙面のページ番号、目次の番号、実ページ順序は異なる場合があり、ブラウザーの `#page=N` は実順序を使います。複数ページの Chunk に単一 page しか記録しなければ引用が不完全となり、失敗調査や評価で根拠の所在を特定しにくくなります。

## 決定

ページ別に抽出し、ページ内で独立して分割・重複を作ります。Chunk は常に 1 個の物理ページ番号を持ち、番号は 1 から始まります。size は抽出文字数で token 数ではありません。size/overlap は設定可能ですが overlap は size 未満。索引 ID にアルゴリズム版、size、overlap、サービス、Embedding モデルを含め、変更時は再構築します。

複数ページの質問は複数 Chunk で回答し、同一主張が複数ページを引用できます。隣接ページを強制結合せず、評価にも複数ページ問題を残し、`(document_id, physical_page)` でラベル付け・採点します。

## 理由と効果

- 引用ごとに実 PDF ページへ戻れ、抜粋・ページ・出典をサーバーが対応付けます。
- 再構築、削除、診断をページで特定でき、Chunk 設定を変えても評価ラベルが失効しません。
- 同じページ単位 ground truth で size/overlap を比較し、Chunk ID 変更によるラベル偏りを減らします。

## 代償と未解決事項

ページをまたぐ文・表・見出しと本文は分断され、全根拠に複数ページ検索が必要です。短いページでは短い Chunk ができ、overlap でもページ間の意味は補えません。段組み順序、複雑な表、スキャン品質は抽出/OCR に依存し、この決定だけでは改善しません。

将来は隣接ページの検索拡張や親子 Chunk を追加できますが、各テキストの物理ページ対応を保持します。複数ページ Chunk を採るなら、出典をページ範囲・複数位置へ拡張し、引用位置と評価方式を再設計する必要があり、現在の単一 page は流用できません。

## 検証

`tests/test_pipeline.py` はページ境界・重複、`tests/test_evaluation.py` は複数ページラベル・指標を検証し、`scripts/chunk_experiment.py` が同じデータで比較します。[Chunk 実験](../../reports/chunks/chunk-experiment-local.md)を参照してください。
