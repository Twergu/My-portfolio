# v3 Verifier / Judge の不一致診断

[strict の問題別原本](quality-strict-test.json)、[fast の原本](quality-fast-test.json)に基づく、AI による保存出力・コード・根拠の再確認です。人手ラベルではなく、凍結 test の採点やプロンプトも変えていません。

`false_refusal` は「回答可能な問題で検証済み回答を返せない」という既定義です。strict の 4/42 には実際の回答誤りの正しい遮断も含み、「Verifier が 4 回間違えた」とは言えません。`unsupported_answer` は遮断イベントで、無根拠な回答が利用者へ届いた意味ではありません。

| 標本 | 観測 | 解釈 |
|---|---|---|
| strict boreal-en-05 | 原文は領収書なしでは精算不可。引用の 2 ページ目に正社員の範囲が再掲されていないとして拒否 | 範囲は同文書 1 ページ目にあるが当該主張は 2 ページ目のみ引用。範囲引用の追加か文脈契約の見直しが必要で、全主張を単純に緩めるべきではない |
| strict boreal-en-12 | 草案は未承認・未発効なのに、質問の月と出張分類の逐語的記載を要求 | 日付・表現への過剰要求の可能性。dev 校正で全体改善は示せず、この test でプロンプトを調整しない |
| strict boreal-ja-04 | 9 暦日と 3 営業日を区別。最初は前者のみ引用し、次の引用で後者が取消申請に属すと説明 | 個別検証では最初の否定部分に必要な別箇所を引用していない。各主張の引用を完全にする必要があり、全検索結果を暗黙の引用として扱わない |
| strict boreal-ja-09 | 例外上限 22500 円に Generator が「税込み」を付加したが、例外の引用に税の記載なし | 拒否には根拠がある。一般制度の税条件は証明なしで例外へ継承できない。Judge が追加限定を見逃して誤って正確・根拠ありとした |
| fast boreal-zh-04 | 正確性 Judge は「3 営業日は取消申請の期限」という補足で 0、引用 Judge は支持 | 実引用の運用条件ページに補足の根拠がある。正確性 Judge が見る gold の欠落と、正しい補足の採点境界の問題。元 0 を手動で上げない |

Judge の入力分離は未引用 gold の流用を防ぎますが、モデル誤りや参照根拠の欠落を消せません。校正・最終データには業務担当者のレビューが必要です。当時は依頼で保留しており、レビュー済みと偽りません。

## 構造化出力と誤拒否の費用

strict 全実行中に再ランキングの形式失敗が 1 回あり、制限付きの形式修正 1 回で回復しました。全試行と tokens を集計し、欠落 verdict を通過にしません。strict の quote 不一致は 0、根拠遮断は 4。fast の quote 不一致は 0、意味的 Verifier はなく、回答可能な 2 問を Generator が拒否しました。

strict 候補 59 主張の selective オフライン再評価では、「高リスク内容なし・完全な単一段落の原文抜粋」の省略条件を満たすものはなく、省ける Verifier 呼び出しは 0。保守的方針の実際の対象範囲であり、有料 selective の時間実測ではありません。

次は新 dev と業務レビューにより引用範囲、日付推論、税限定、gold 網羅性、安全な言い換えを補い、方式を凍結して新 test を評価します。strict/all を既定に保持し、fast の 1 回の自動スコアが高いだけで根拠検証を外しません。
