# 依据验证分歧：原文复核

范围：冻结的 900/0 strict test 中 3 个 `unsupported_answer` 案例。以下为 Codex 按已保存原文进行的事后分析，不是独立人工标注；没有再调用模型、改评分或根据 test 调提示词。原始数据见 [逐题 JSON](chunks-api/chunk-api-selected-test.json)。

自动 Judge 将这 3 个被拦截候选都判为正确且有依据，但这不代表 3 次拦截都错误。`grounding_rejected_correct_and_grounded = 1.0, n=3` 应解释为自动诊断值。

| 案例 | Runtime Verifier / 独立 Judge | 按原文复核的判断 |
|---|---|---|
| `boreal-en-12`：草案是否允许 2026 年 3 月报销 30,000 日元 | Verifier 认为引用没有明确写出 2026 年 3 月，拒绝“不允许”的答案；Judge 认为支持 | 草案明确未批准、未生效且不可用于当前报销。Verifier 对否定规则套用具体时间可能过严，属于值得复核的误拦截候选，不能只按日期词面缺失判错。 |
| `boreal-zh-09`：会议例外的酒店上限和发票期限 | Verifier 接受 22,500 日元金额，但拒绝“含税”；Judge 全部接受 | 候选引用一般规则的含税 16,800 日元与例外的 22,500 日元。能否继承一般税务口径应由制度语义明确，不能仅靠金额匹配；属于规则继承存在歧义的案例。 |
| `boreal-ja-02`：2025 年 12 月旧版上限 | 候选增加 `税込みではない`（并非含税），Verifier 因原文没有税务口径而拦截；Judge 却判正确且有依据 | 旧版只规定一晚 13,800 日元，未说明是否含税。新增否定断言没有证据；Verifier 的拦截合理，Judge 把关键数字正确当成整体正确，漏掉了不受支持的附加事实。 |

第三个案例的关键原文为：

> 適用期間は2024年1月1日から2025年12月31日。正社員の宿泊上限は1泊13800円、領収書は帰着後15暦日以内。

候选中出现了：

> 宿泊上限として税込みではない1泊13,800円

前者没有支持后者的“并非含税”。该候选已经被应用拦截，没有展示给用户。它揭示的是额外 Evaluation Judge 的局限，不能用来改写“已交付答案”的原始 Citation Groundedness 分数，也不能把自动分数宣传成人工确认的 100% 可靠性。

后续应在新的开发数据上补充税务口径、否定附加事实与规则继承标签，开展多模型/人工盲审校准，再用新的冻结测试集验收。当前保留原始测量与分歧，不通过修改 test 标签或删除反例提高成绩。
