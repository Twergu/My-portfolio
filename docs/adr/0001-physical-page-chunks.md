# ADR 0001：每个 Chunk 不跨 PDF 物理页

状态：接受。适用于 `backend/rag.py::chunks_from_pages`。

## 背景

用户需要从回答回到上传的原 PDF 核对依据。PDF 的纸面页码、目录页码和实际页序可能不同；浏览器的 `#page=N` 使用实际页序。若一个片段跨页，只记录一个 page 会让引用不完整，也难以在失败排查与评估中确定证据落在哪一页。

## 决定

逐页提取文字，每页内部独立分块和重叠。一个 Chunk 始终只有一个物理页码；页码从 1 开始。分块大小按提取文本的字符数计算，不是 token 数。size 和 overlap 可配置，但 overlap 不能达到 size。索引身份包含算法版本、size、overlap、模型服务与 Embedding 模型，参数变化后需要重建索引。

跨页问题通过检索多个 Chunk 回答，一条断言可同时引用多页资料，不把相邻页强行拼成一个来源。评估集专门保留跨页问题，并以 `(document_id, physical_page)` 标注和计分。

## 理由与效果

- 每一处引用可以精确回到 PDF 的实际页，原文摘录、页码和来源由服务器映射。
- 分块重建、删除和错误诊断可定位到明确页面，评估标签不随 Chunk 参数变化而失效。
- 比较 size/overlap 时可以保留相同的页级 ground truth，减少因 Chunk ID 改变带来的标签偏差。

## 代价与未解决问题

跨页句子、表格、标题与正文可能被切开，因此检索需要召回多页才能得到完整依据；短页也可能产生较短的片段，重叠不能弥补跨页语义。多栏阅读顺序、复杂表格和扫描件质量依赖 PDF 提取/OCR，这个决定本身不能改善提取质量。

后续可以增加邻页扩展检索或父子 Chunk，但必须保留每段文字各自的物理页映射。若采用跨页 Chunk，需要将来源升级成页区间或多个证据位置，并重做引用定位和评估协议，不能复用当前单页字段。

## 验证

`tests/test_pipeline.py` 检查页边界与重叠，`tests/test_evaluation.py` 检查跨页标注和指标，`scripts/chunk_experiment.py` 在相同数据上比较分块参数。结果见 [Chunk 实验报告](../../reports/chunks/chunk-experiment-local.md)。
