# 単一プロセス Agent の実行境界

この段階では Redis、分散キュー、会話の永続化は導入しません。Uvicorn プロセスごとに独立した `AgentService` を持つため、**worker 1 個 / インスタンス 1 個**で実行してください。複数 worker へのランダム振り分けでは他プロセスのタスクを参照できず、スティッキールーティングも永続性を保証しません。

| 動作 | 現在の契約 |
| --- | --- |
| セッション保存 | メモリ上の running / needs_input のみ。最終回答・例外後に解放 |
| 所有者 | ランダム task_id をサーバー認証ユーザーに結び付け、他人には 404 |
| TTL | 作成から 900 秒の絶対期限。追加情報では延長せず、後続リクエストで遅延清掃 |
| 失効 | 待機タスクの再開・取消は 404。遅い追加確認の終了時に失効済みなら task_expired とし、不正な再開ハンドルを返さない |
| 実行中 | TTL は強制中断ではない。busy タスクは容量に含み、別リクエストで削除できない。送信済みモデル要求は強制撤回しない |
| 同時実行 | プロセス全体で最大 100 タスク、ユーザー別に 4。待機・実行中とも含み、超過は 429 |
| 同一タスクの競合 | ロック内で busy を確保し、重複 reply / cancel は 409。2 本目の Planner/ツール経路を開始しない |
| 取消 | 追加情報待ちのみ取消可能。実行済み読み取りツールとモデル費用は取り消せない。実行中は応答を待つ |
| ブラウザーを閉じる | 同期 HTTP モデル要求は継続する場合がある。切断は取消・返金を保証しない。容量・失効規則は適用 |
| 再起動 / 障害 | 待機状態を失い旧 task_id は 404。DB の文書・ベクトル・ACL はメモリタスクとともには消えない |
| 権限 / 根拠変更 | 各モデル呼び出し前と応答前に ID、ACL、設定、文書・Chunk を再確認。変更で旧タスクを無効化し、再開には新規作成が必要 |
| 操作予算 | 既定で Planner 最大 8 回、ツール試行 6 回、ユーザー入力 4 ターン。再開でリセットしない。入力・根拠にも長さ制限 |

プロセス内の資源制約であり、分散レート制限、耐久キュー、全体の API 費用上限ではありません。複数ユーザーのモデル呼び出しは並行し得ます。Provider のタイムアウト・有限再試行は TTL と独立です。Agent は読み取り検索と決定的な計算・日付ツールのみで、メール、承認、DB 更新などの業務書き込みはありません。

実スレッドで同一タスクの reply / cancel を競合させ、モデル経路が 1 回のみになることをテストします。TTL 境界、延長なし、例外時容量解放、ユーザー間の全体容量、再起動の状態消失、失効取消の一貫性も対象です。DB 契約は SQLite と CI の実 PostgreSQL/pgvector で実行します。

## Policy Evidence の境界

自由文の主張は現在適用可能な Document Evidence を引用する必要があります。実検索の文書・Chunk・物理ページ ID、`policy_status=current`、タスク日付と矛盾しない有効期間が必要です。アップロード後 `unclassified` の文書は文書パネルで状態を確認します。通常 RAG の動作は維持します。明示的 `filters.as_of` では、その日を含む過去の archived 制度を使えますが、草案は正式な許可の根拠になりません。

ツールと自己申告は別の出所です。計算は Generator が `calculation_source_id` を返し、サーバーが構造化結果から 3 言語の主張と固定引用を作ります。モデルは文、数値、単位、出典を上書きできません。単位は対応する被演算数の原文が必要で、自動換算・次元推論はしません。有効文書のない自由文の業務許可は遮断し、User Input 単独では規則を成立させません。全生成内容は Strict/all を通ります。[変更報告](agent-followup-report.md)を参照してください。

決定的チェックは出所種別と有効範囲を確認するもので、自然言語推論の証明ではありません。受理候補にも `strict + all` で quote、数値、条件、否定、範囲、同じ claim の全根拠を検証します。有効でも無関係な文書で意味的 Verifier を迂回できません。事実・関連性にはモデル誤判定のリスクが残ります。
