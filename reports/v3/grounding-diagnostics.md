# v3 Verifier / Judge 分歧诊断

来源：[strict 原始逐题报告](quality-strict-test.json)、[fast 原始逐题报告](quality-fast-test.json)。这是基于保存输出的 AI 源码与证据复核，不是人工审核标签，也没有据此修改冻结的 test 评分或调提示词。

`false_refusal` 的既定定义是“可回答问题没有交付通过检查的回答”。因此 strict 的 4/42 包括真正的回答错误被正确拦截，不能直接说成“Verifier 错了 4 次”。`unsupported_answer` 是拦截事件，不表示用户收到无依据答案。

| 样本 | 观察 | 解释 |
|---|---|---|
| strict boreal-en-05 | 原文明确无收据不能报销；Verifier 因被引用的第 2 页没有重述正式员工范围而拒绝 | 范围证据在同一文档第 1 页，但该断言只引用第 2 页。属于需要补充范围引用或调整上下文协议的候选，不应简单放宽全部断言 |
| strict boreal-en-12 | 草案明确未批准、未生效；Verifier 仍要求原文逐字提及问题中的月份与出差类别 | 过度要求日期或措辞的疑似误拒；校准 dev 没有显示提示词整体改善，暂不据此修改 test 上的提示词 |
| strict boreal-ja-04 | 回答区分 9 暦日和 3 営業日；第一个断言仅引用前者，第二个断言的引用明确指出后者属于取消申请 | 分别验证时，第一个断言未引用支持否定部分的另一段。需要更完整的逐断言引用；不能把所有检索结果默认视为被引用证据 |
| strict boreal-ja-09 | 例外制度上限 22500 円被生成器增加“税込み”；该断言引用的例外段没有税额说明 | Verifier 的拒绝有依据。普通制度的含税条件不能未经证明移植到例外；Judge 忽略了多出的限定词，错误地给出正确且有据 |
| fast boreal-zh-04 | 正确性 Judge 因额外解释“3 个工作日是取消申请期限”给 0；引用 Judge 却确认它有依据 | 实际引用的运作条件页确实包含该解释。正确性 Judge 只看 gold 页，暴露 gold evidence 不完整与额外正确解释的评分边界。保留原始 0，不手工抬分 |

两种质量 Judge 的输入隔离避免引用评分借用 gold evidence，但不能消除模型错误或参考证据遗漏。校准和最终数据都需要真实业务审核；用户已明确暂缓这一阶段，本轮不伪造已审核状态。

## 结构化输出与误拒成本

strict 完整运行中，重排出现 1 次格式失败，进行一次限定格式修复后成功；所有尝试与 tokens 已计入结果。没有缺失 verdict 被默认放行。strict 的 quote 匹配失败为 0，依据校验拦截为 4；fast 的 quote 匹配失败为 0，无语义 Verifier，另有 2 个可回答问题被 Generator 拒答。

59 条 strict 候选断言的 selective 离线回放中，没有一条符合“无高风险内容、完整单段原文摘录”的跳过条件。可省掉的 Verifier 调用数为 0。这是保守策略的真实覆盖结果，不代表付费 selective 模式已经做过延迟实测。

下一轮应在新的 dev 数据和业务审核结果上补充引用范围、日期推理、税额限定词、gold evidence 覆盖与安全改写，再冻结协议评估新 test。当前保留 strict/all 默认值，不因为 fast 的单次自动评分更高就取消依据验证。
